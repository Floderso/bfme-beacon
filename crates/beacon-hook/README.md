# beacon-hook — `wsock32.dll` proxy for `lotrbfme.exe`

The 32-bit DLL Beacon puts into the BFME game folder (architecture §2, §3, §4.2–§4.4,
§5; spec 03 §8–§9, spec 04 §3, §5). `WSOCK32` is not a KnownDLL, so the game loads
this file instead of `SysWOW64\wsock32.dll`. The DLL is **inert unless armed**; when
armed it turns the game's LAN sockets into *virtual sockets* that talk only to the
Beacon agent on loopback (`BCN1` frames, `beacon_proto::local`).

```sh
. /d/BFME-RE/env.sh
cargo hook            # -> <target>/i686-pc-windows-gnullvm/release-hook/wsock32.dll
python crates/beacon-hook/tools/check_exports.py <target>/i686-pc-windows-gnullvm/release-hook/wsock32.dll
cargo hook-harness    # 32-bit harness, 7 scenarios in child processes (crates/beacon-hook-harness)
cargo test -p beacon-hook [--target i686-pc-windows-gnullvm]
```

Target `i686-pc-windows-gnullvm`, profile `release-hook` (`panic = "abort"`, fat LTO).
The only dependency is `beacon-proto` with `default-features = false` (no crypto, no
serde). Win32 functions are declared in `src/ffi.rs` and linked from llvm-mingw's
import libraries; the DLL imports `ws2_32`, `kernel32`, `ntdll`, `msvcrt` and an API
set (std's futex lock) — never `wsock32` itself and never through the game's IAT.

## Exports

All 75 named exports of `SysWOW64\wsock32.dll` 10.0.26100 with **identical names
and ordinals** (`wsock32.def`, generated by `tools/gen_def.py` with pefile and
committed; the build script passes it to lld, which uses the last `/def`):

* **27 implemented in Rust** (`src/exports.rs`, internal stdcall symbols
  `_bh_<name>@N`, the `.def` maps e.g. `bind=bh_bind@12 @2`): the 23 names
  `lotrbfme.exe` imports from WSOCK32 (`WSACleanup WSAGetLastError WSAStartup
  __WSAFDIsSet accept bind closesocket connect gethostbyname gethostname getpeername
  getsockname htonl inet_addr inet_ntoa ioctlsocket listen ntohs select send sendto
  shutdown socket`) plus the four WinSock 1.1 *code* exports `getsockopt` #7,
  `recv` #16, `recvfrom` #17, `setsockopt` #21 (spec 03 §8.3).
* **48 forwarders** spelled exactly like the system DLL (`htons=ws2_32.htons @9`,
  `AcceptEx=MSWSOCK.AcceptEx @1141`, …).

`tools/check_exports.py` compares a build with the system DLL (machine, names,
ordinals, forwarder strings, implemented exports are code, imports) and exits 1 on
any difference. Run it after every `cargo hook`.

### The four WinSock 1.1 code exports (`src/compat.rs`)

`worldbuilder.exe` imports `getsockopt/setsockopt/recv/recvfrom` from WSOCK32, so
passive mode must keep the system code's semantics. Disassembled from the system
DLL (capstone) and re-implemented exactly:

* `IPPROTO_IP` options are renumbered WinSock 1.1 → 2 (2→9 `IP_MULTICAST_IF`,
  3→10, 4→11, 5→12, 6→13, 7→4 `IP_TTL`, 8→3 `IP_TOS`, 9→14 `IP_DONTFRAGMENT`;
  jump table at RVA 0x1539).
* `IPPROTO_TCP`/`TCP_BSDURGENT` (0x7000) → `TCP_EXPEDITED_1122` (2), boolean
  inverted (setsockopt passes `!optval[0]` as a 4-byte int when `optlen >= 4`
  (unsigned compare); getsockopt inverts the returned byte).
* `getsockopt` returns 0/-1 (normalised); `setsockopt` returns ws2_32's value.
* `recv`/`recvfrom` call `WSARecv`/`WSARecvFrom`; a `MSG_PARTIAL` result returns the
  negated byte count with `WSAEMSGSIZE`.

The harness compares the IP-option renumbering, error codes and empty-socket results
with the real system DLL loaded side by side.

## Modes

| Mode | When | Behaviour |
|---|---|---|
| **Passive** | `BEACON_AGENT_PORT` unset, **or** the host exe fails the identity check (e.g. `worldbuilder.exe`) | Every export calls ws2_32 directly (or `compat`), no IAT patch, no threads, nothing logged (only `BEACON_AGENT_PORT` and the test flag are read). |
| **Passive + logged error** | `BEACON_AGENT_PORT` set, identity OK, but `BEACON_AGENT_PORT`/`BEACON_LOCAL_TOKEN`/`BEACON_VIP` unusable, or the WS2_32 patch set fails | As passive; one explanatory log line at the first `WSAStartup`. |
| **Armed (exe)** | `BEACON_AGENT_PORT` set + identity check passed + valid config | IAT patches below, socket virtualisation. |
| **Armed (test)** | `BEACON_TEST_ARMED_WITHOUT_EXE=1` | Socket virtualisation in any process, **no identity check, no IAT patch at all** (harness only). |

Identity check (spec 03 §8.4, in-memory headers of `GetModuleHandleW(NULL)`):
`TimeDateStamp == 0x438BABC8`, `SizeOfImage == 0x01016000`, and the `WS2_32.dll`
import descriptor has `FirstThunk == 0x00F58CB0` and imports exactly `WSAIoctl,
getsockopt, recv, recvfrom, setsockopt` in this order. Verified against the
installed `C:\BFME1\lotrbfme.exe` (passes) and `worldbuilder.exe` (fails → passive)
by a unit test that maps the files like the loader (skipped where BFME is absent).

`DllMain(PROCESS_ATTACH)` only reads the environment, checks the identity, patches
IAT slots and publishes the armed state — no threads, sockets, `LoadLibrary` or file
I/O under the loader lock. The first `WSAStartup` writes the start-up report to the
log and re-verifies the patches, because another module (e.g. the compatibility
shim engine, which can patch imports after the DLL initialisers) may have changed a
slot meanwhile:

* a slot that holds the loader's original again is patched again;
* a WS2_32 slot that holds a third module's function is **probed**: the function is
  called with a sentinel socket (`ws2::reaches_hook`, `0x7FFFFFF3`, thread-checked;
  ws2_32 answers `WSAENOTSOCK` if the call never reaches us). If our hook is reached
  (the other hook is chained in front of ours) the slot is left alone. If it is
  not, the game would bypass `recvfrom`/`recv` and see raw `DELIVER` frames from
  `127.0.0.1` while its `bind`/`sendto` are virtualised — so the hook **disarms**:
  every export is passive from then on (empty LAN, one log line). It never
  re-patches over a foreign hook, because chaining to it could loop back into us;
* an optional slot (registry, mutex, AppData) changed by a third module is left
  alone and logged.

## Environment

| Variable | Meaning |
|---|---|
| `BEACON_AGENT_PORT` | Agent's loopback UDP port; arms the hook (architecture §4.3). |
| `BEACON_LOCAL_TOKEN` | u32 hex, written into every REG/SEND/CLOSE frame. Required. |
| `BEACON_VIP` | Player vIP `198.18.0.2…254`. Required. |
| `BEACON_SERIAL` | 20 × `[A-Z0-9]`; returned for the `ergc` CD-key read. Missing/malformed → the registry value passes through (logged). |
| `BEACON_MULTI` | `1` = test mode (two instances on one PC); needs `BEACON_USERDIR`. |
| `BEACON_USERDIR` | Absolute path (`X:\…` or `\\server\…`, ≤ 200 chars, the game appends its leaf folder in `MAX_PATH` buffers) returned for `CSIDL_APPDATA`. |
| `BEACON_LOG` | Log file (appended). Without it nothing is ever written. |
| `BEACON_LOG_LEVEL` | *hook-local*: `debug` adds one line per datagram. |
| `BEACON_TEST_ARMED_WITHOUT_EXE` | *hook-local*: `1` = armed test mode (see above). |

`BEACON_PATCHES` (architecture §10) is not used yet.

## IAT slots patched (exe mode)

Found by walking the import table **by name**; RVAs as listed by pefile for the
installed `lotrbfme.exe` (the unit test asserts them). Only slots the exe really
imports are patched.

| Import | Slot RVA | When | Hook |
|---|---|---|---|
| `WS2_32!WSAIoctl` | `0x00F58CB0` | always | chain to original (real socket) |
| `WS2_32!getsockopt` | `0x00F58CB4` | always | chain to original (real socket) |
| `WS2_32!recv` | `0x00F58CB8` | always | virtual sockets: as `recvfrom` without `from`; else original |
| `WS2_32!recvfrom` | `0x00F58CBC` | always | virtual sockets (below); else original |
| `WS2_32!setsockopt` | `0x00F58CC0` | always | chain to original (real socket) |
| `ADVAPI32!RegQueryValueExA` | `0x00F59154` | `BEACON_SERIAL` valid | `ergc` default value → serial |
| `ADVAPI32!RegQueryValueExW` | `0x00F59158` | `BEACON_SERIAL` valid | same, UTF-16 |
| `KERNEL32!CreateMutexA` | `0x00F58CF4` | `BEACON_MULTI=1` | `"LOTRMilesAudioManagerMutex"` → `…-<PID>` |
| `KERNEL32!CreateMutexW` | `0x00F58CF8` | `BEACON_MULTI=1` | `L"E99E8455-CC9B-488a-BA22-0E8A8F74F9FA"` → `…-<PID>` |
| `SHELL32!SHGetSpecialFolderPathA` | `0x00F59170` | `BEACON_MULTI=1` | `CSIDL_APPDATA` → `BEACON_USERDIR` (ANSI, `CP_ACP`) |
| `SHELL32!SHGetSpecialFolderPathW` | `0x00F59174` | `BEACON_MULTI=1` | `CSIDL_APPDATA` → `BEACON_USERDIR` |

The five WS2_32 slots are all-or-nothing (spec 03 §9.11: virtualising without the
`recvfrom` hook would deliver wrong `from` addresses); a refused slot (null, or
pointing into the exe = not resolved) undoes the others and the hook stays passive.
Each patch stores the previous pointer first and chains to it.

**ergc**: the game reads `RegOpenKeyExA(HKLM, "SOFTWARE\Electronic Arts\EA Games\The
Battle for Middle-earth\ergc", KEY_READ)` + `RegQueryValueExA(h, "")`, falling back to
HKCU (spec 04 §5.1/§5.2, Open-BFME `RegistryGetAsciiString.cpp`). The hook answers a
default-value read (`""`/NULL) whose key handle `NtQueryKey(KeyNameInformation)`
names exactly that key under `\REGISTRY\MACHINE` (incl. `WOW6432Node`),
`\REGISTRY\USER\<sid>` or the UAC VirtualStore copy, with `REG_SZ` + documented
buffer semantics (size query, `ERROR_MORE_DATA`). If the key does not exist the game
reads an empty serial, which BFME's dupe check accepts.

## Socket virtualisation (architecture §4.2, §5)

* `socket(AF_INET, SOCK_DGRAM, 0|17)` → real socket, remembered as candidate.
* `bind` to the VIP (any port; port 0 → ephemeral vport from 49152) or to
  `0.0.0.0:8086…8101` → **virtual**: real `bind(127.0.0.1:0)`, `SIO_UDP_CONNRESET`
  off, `REG` from the socket to `127.0.0.1:BEACON_AGENT_PORT`. A vport already held
  by another virtual socket of the process → `WSAEADDRINUSE` (BFME's port probing).
  Other binds are real and untouched.
* `sendto(virtual)` to `198.18.0.0/24`, `255.255.255.255` or `198.18.0.255` → one
  `SEND` frame from the same socket, returns `len`. Other destinations are dropped
  silently (returns `len`). Native errors kept: broadcast without `SO_BROADCAST` →
  `WSAEACCES` (read from the real socket), `len > 1024` → `WSAEMSGSIZE`, port 0 →
  `WSAEADDRNOTAVAIL`, bad `to` → `WSAEFAULT`/`WSAEAFNOSUPPORT`.
* `recvfrom`/`recv(virtual)` → loop over the real `recvfrom` into a 2 KiB stack
  buffer: only datagrams from `127.0.0.1:BEACON_AGENT_PORT` with a valid `DELIVER`
  header are accepted; the payload is copied to the caller's buffer, `from` =
  `{src vIP, src vport}`. Foreign, garbage, truncated-header and oversize (> 480)
  datagrams are discarded (consumed even under `MSG_PEEK`). If nothing valid is
  queued the real result is returned (`WSAEWOULDBLOCK` on a non-blocking socket).
  A payload larger than the caller's buffer is truncated with `WSAEMSGSIZE` (Winsock
  semantics). `WSAECONNRESET`/`WSAENETRESET` are swallowed (the game sees silence if
  the agent is gone). At most 1024 discards per call, then `WSAEWOULDBLOCK`.
* `getsockname(virtual)` → `{VIP or 0.0.0.0, vport}`.
* `gethostname` → `BEACON-<last octet>`; `gethostbyname` of that name, the real host
  name, `""` or NULL → static `hostent` with exactly one address, the VIP.
* `shutdown(SD_SEND|SD_BOTH)` sends `CLOSE` first (afterwards the socket cannot send;
  BFME's `UDP` destructor is `shutdown(SD_BOTH)` → drain → `closesocket`);
  `closesocket` sends `CLOSE` unless already sent, forgets the entry, closes.
* `setsockopt/getsockopt/ioctlsocket/select/shutdown/WSAGetLastError` act on the
  real loopback socket (native semantics, non-blocking mode included).

Bookkeeping: fixed table of 64 entries (`src/vtable.rs`) behind a `std` mutex,
held only for table operations, never across a system call. No allocation and no
threads anywhere; the hot path uses stack buffers. Stale entries (sockets closed
behind the hook's back, e.g. by another module calling ws2_32 directly or by the
process's last `WSACleanup`) are dropped when `socket`/`accept` hand out the same
handle value again (a new TCP socket on a reused handle must not be treated as the
old virtual one), and are detected by a liveness check (`getsockname` must still
show the recorded loopback port) when they block a bind or the table is full.

## Logging

Only with `BEACON_LOG`, and only once the hook got past the passive checks. One
`WriteFile` per line (stack-formatted, `HH:MM:SS.mmm [pid] …`), opened lazily,
last-error value preserved. Rate limit 40 lines/s and 20 000 lines per process
(debug: 500/s, 200 000); suppressed lines are counted on the next line. Logged:
start-up report (mode, vIP, host name, agent port, which slots were patched),
configuration problems, bind/REG/CLOSE, ergc/mutex/AppData substitutions; with
`BEACON_LOG_LEVEL=debug` also every SEND, DELIVER and discarded datagram. The token
is never logged.

## Limitations / deviations

* Deliberate deviation from spec 03 §9.3 (per-peer injector sockets): DELIVER frames
  carry a 12-byte header that `recvfrom` strips (architecture §4.2/§5). Therefore
  `ioctlsocket(FIONREAD)` and `select` readability on a virtual socket count the
  header and not-yet-discarded foreign datagrams. BFME's LAN path never uses them.
* `connect`/`send`/`getpeername`/`listen`/`accept`/`WSAIoctl` on a virtual socket
  act on the real loopback socket (a UDP `connect` would stop agent deliveries);
  BFME never calls them on LAN sockets.
* No `CLOSE` if the process exits without `closesocket`/`shutdown`; the agent must
  expire registrations on its own (it learns endpoints from every `SEND` anyway).
* `gethostbyname(own name)` returns the VIP for every caller, including the
  (unused) GameSpy/WWDownload paths.
* `BEACON_USERDIR` that is not representable in the ANSI code page: the A variant of
  `SHGetSpecialFolderPath` passes through (maps/replays then share the real
  folder); logged. (With the UTF-8 ANSI code page every path is representable.)
* Exe mode is exercised by the harness (`exe-mode`) in a copy of the harness exe
  whose in-memory image gets the game's identity before its loader runs, so the
  real loader snaps the IATs and runs `DllMain` at process start; it is not
  exercised in the running game here (the game must not be launched by the
  build/test tooling).
* The re-verification probe calls a foreign hook with an invalid socket; a foreign
  hook that refuses invalid sockets without calling the next function looks like
  a bypass, so the hook disarms (fail safe: empty LAN, logged) rather than risk a
  call loop. Slots changed after the first `WSAStartup` are not detected.
* In the system code, `setsockopt(IPPROTO_TCP, TCP_BSDURGENT)` with `optval == NULL`
  and `optlen >= 4` crashes; the proxy passes it to ws2_32 (`WSAEFAULT`) instead.
